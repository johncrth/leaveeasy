# 🧪 ชุดทดสอบอัตโนมัติของ LeaveEasy

> 📖 **การทดสอบอัตโนมัติ** คือการให้โปรแกรมเปิดเบราว์เซอร์ กดปุ่ม และกรอกฟอร์มแทนเรา
> แล้วบอกว่าผลที่ได้ตรงกับที่ควรจะเป็นหรือไม่ · เครื่องมือที่ใช้ชื่อ **Playwright**

**ทำไมต้องมี:** ก่อนสาธิตสด เรากดเองทีละหน้าไม่ไหวและมักลืมกรณีที่เคยพัง
เทสต์ชุดนี้กดให้ครบทุกครั้งภายในไม่กี่นาที

---

## 📋 เทสต์ในชุดนี้มีอะไรบ้าง

| ไฟล์ | ทดสอบอะไร |
|---|---|
| `main-flow.spec.js` | **เส้นทางหลัก** — ยื่นใบลา → ใบใหม่โผล่ในรายการ → เปิดดูรายละเอียดได้ |
| `validation.spec.js` | **กรอกไม่ครบ** — กดบันทึกโดยไม่กรอก · วันที่สิ้นสุดย้อนหลัง · ส่งความเห็นว่างเปล่า |
| `security.spec.js` | 🔒 **ความปลอดภัยแบบสวมรอย** — ไม่ล็อกอินอ่านไม่ได้ · ล็อกอินเป็นคนหนึ่งแล้วเปิดใบลาของอีกคนไม่ได้ |
| `ai-button.spec.js` | 🤖 **ปุ่ม AI ล้มแล้วไม่ค้าง** — ตัดการเชื่อมต่อไป OpenRouter แล้วต้องยังบันทึกใบลาเองได้ |

> ⚠️ **ห้ามแก้โค้ดเพื่อให้เทสต์ผ่าน** — เทสต์ที่ไม่ผ่านคือเทสต์กำลังบอกอะไรบางอย่าง
> ให้แยกให้ออกก่อนว่า **โค้ดผิด** หรือ **เทสต์เขียนผิด** แล้วค่อยแก้ที่ต้นเหตุ
> โดยเฉพาะ `security.spec.js` — ถ้าไม่ผ่าน แปลว่าข้อมูลรั่วจริง ให้ไปแก้ `firestore.rules`

---

## ขั้นที่ 1 — ติดตั้ง ⏱ ~3 นาที (ทำครั้งเดียว)

```bash
npm install
npx playwright install chromium
```

**จะเห็น:** ข้อความดาวน์โหลดเบราว์เซอร์วิ่งขึ้นมา ใช้เวลา 1–3 นาที

---

## ขั้นที่ 2 — เตรียมบัญชีทดสอบ ⏱ ~3 นาที (ทำครั้งเดียว)

เทสต์ต้องล็อกอินจริง จึงต้องมี **บัญชีทดสอบ 2 บัญชี**

1. เปิดเว็บ → หน้า `login.html` → **สมัครสมาชิก 2 บัญชี**
   ใช้อีเมลสมมติ เช่น `test-a@example.com` และ `test-b@example.com`
2. ล็อกอินเป็นบัญชี ก. แล้ว **ยื่นใบลา 1 ใบ**
3. เปิด **Firebase Console → Firestore → `leaveRequests`** แล้ว **จดรหัสไฟล์ (Document ID)** ของใบลานั้นไว้

> ⚠️ ใช้อีเมลสมมติเท่านั้น **ห้ามใช้อีเมลจริงของใคร** และห้ามเขียนรหัสผ่านลงไฟล์ที่จะ commit

---

## ขั้นที่ 3 — สั่งรัน ⏱ ~2 นาที

ตั้งค่าบัญชีทดสอบก่อน แล้วสั่งรันในหน้าต่างเดียวกัน

**บน Windows (PowerShell)**

```powershell
$env:TEST_EMAIL_A="test-a@example.com"
$env:TEST_PASSWORD_A="รหัสผ่านของบัญชี ก."
$env:TEST_EMAIL_B="test-b@example.com"
$env:TEST_PASSWORD_B="รหัสผ่านของบัญชี ข."
$env:TEST_REQUEST_ID_A="รหัสใบลาที่จดไว้"
npm test
```

**บน macOS หรือ Linux**

```bash
TEST_EMAIL_A="test-a@example.com" TEST_PASSWORD_A="..." \
TEST_EMAIL_B="test-b@example.com" TEST_PASSWORD_B="..." \
TEST_REQUEST_ID_A="..." \
npm test
```

**จะเห็น:** รายชื่อเทสต์วิ่งขึ้นมาทีละบรรทัด
บรรทัดที่ผ่านขึ้นเครื่องหมายถูก บรรทัดที่ไม่ผ่านขึ้นสีแดงพร้อมบอกว่าคาดหวังอะไรแต่ได้อะไร

> 💡 **ถ้าไม่ได้ตั้งค่าบัญชีทดสอบ เทสต์จะขึ้นว่า skipped (ข้าม) ไม่ใช่ failed**
> เป็นแบบนี้ตั้งใจไว้ จะได้ไม่เข้าใจผิดว่าระบบพัง

## คำสั่งที่ใช้บ่อย

| อยากทำอะไร | พิมพ์ |
|---|---|
| รันทั้งหมด | `npm test` |
| รันไฟล์เดียว | `npx playwright test tests/security.spec.js` |
| ดูเบราว์เซอร์ทำงานจริง ๆ | `npx playwright test --headed` |
| เปิดรายงานผลรอบล่าสุด | `npx playwright show-report` |
| ทดสอบกับ URL ที่ deploy แล้ว | ตั้ง `BASE_URL` เป็น URL นั้นก่อนสั่งรัน |

## 🆘 ติดตรงนี้ให้ทำอย่างไร

| อาการ | ทำอย่างไร |
|---|---|
| เทสต์ทุกตัวขึ้นว่า skipped | ยังไม่ได้ตั้งค่าบัญชีทดสอบ — กลับไปทำขั้นที่ 2 และ 3 |
| ล็อกอินในเทสต์ไม่ผ่าน (หมดเวลารอ) | ลองล็อกอินด้วยมือด้วยบัญชีเดียวกันก่อน ถ้ามือยังไม่ได้ แปลว่าปัญหาไม่ได้อยู่ที่เทสต์ |
| `security.spec.js` ไม่ผ่าน | 🔴 **ข้อมูลรั่วจริง** — ไปแก้ `firestore.rules` แล้ว `firebase deploy` ใหม่ · ห้ามแก้เทสต์ |
| `ai-button.spec.js` ขึ้นว่า skipped | ยังไม่ได้ใส่คีย์ใน `js/config.js` (ดู SETUP.md ขั้นที่ 8) |
| เปิดเซิร์ฟเวอร์ไม่ขึ้น / port ชน | ปิดหน้าต่างที่รัน `npm run dev` ค้างไว้ก่อน แล้วสั่ง `npm test` ใหม่ |
| ใบลาทดสอบค้างเต็มระบบ | ลบใบที่ขึ้นต้นด้วย "ทดสอบอัตโนมัติ" ทิ้งใน Firebase Console เป็นระยะ |
